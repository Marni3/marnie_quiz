# Platform Changelog: 2026-09-03

## Deep Diagnostic Audit: Routes, User Interfaces, and Interaction Disconnections

### Context & Objective
Following extensive user testing, critical interaction failures were observed—specifically Refresher buttons bouncing users back to the Library without explanation, Omni-Search failing to filter or navigate to matching modules, and dead links scattered across the reading canvas. A comprehensive forensic audit was conducted across all routes, API handlers, database schema constraints, and client state bindings.

### Core Discoveries & Documented Faults

1. **Refresher Button Silent Fallback Bug**:
   - `platform/components/launch-drill-button.tsx`: On API error, catches the failure and silently calls `router.push('/quizzes')`.
   - `platform/lib/srs.ts` (`assembleDailyRefresherDrill`): Direct database query lacked in-memory mock store fallback. Inserting into `questionSets` failed foreign key validation for guest users (`00000000-0000-0000-0000-000000000001`). Filter logic also queried `isAnchor = true` (0 seeded questions) and failed to pass `dueTopicCodes` into the SQL `where` clause.
   - `platform/components/refresher-customizer-modal.tsx`: Failed requests logged to console with no user-facing feedback.

2. **Omni-Search Disconnection**:
   - `platform/components/omni-search.tsx`: Topics link to `/quizzes?domain=...`.
   - `platform/app/quizzes/library-view.tsx`: Lacks `useSearchParams()`. All incoming URL query parameters (`?domain=...`, `?search=...`) were ignored by client state.
   - Omni-Search omitted 45 out of 46 active learning modules, hardcoding only `geas-10-01`.

3. **Broken Navigation in Module Reader**:
   - `platform/app/learn/[moduleId]/module-reader.tsx`: "Continue Last Module" linked to `/learn/${module.code.toLowerCase()}` (space encoding bug, e.g. `/learn/math%2007-01` $\to$ 404).
   - "Browse Syllabus Library Set" linked to `/quizzes/${module.pairedQuizSetId}` which targeted non-existent `*-mastery` sets $\to$ 404.

4. **Interactive Question Sandbox Guest Lockout**:
   - `platform/app/modules/[questionId]/page.tsx`: Strict `if (!session?.user) notFound()` prevented guest users from opening interactive modules from quiz results.

5. **Mobile Viewport Occlusion & History Inaccessibility**:
   - Fixed bottom navigation bar (`MobileNav`) obscured the lower 64px of all screens due to missing bottom padding on layouts (`pb-20 md:pb-0`).
   - History (`/history`) was hidden on mobile header and omitted from `MobileNav`, leaving mobile students with no path to view past attempt history.

6. **AI Tutor Latency & Lack of Interface Transparency**:
   - `platform/lib/tutor/storage.ts`: Stores keys in isolation without cross-provider fallback or latency monitoring.
   - `platform/app/api/tutor/stream/route.ts`: Hardcoded sequential fallback candidates contain non-existent models (`gemini-3.6-flash`, `gemini-3.5-flash`), incurring multiple consecutive 404 network round-trips and 5–15s of artificial latency.
   - Solution adopted: **Dynamic Cross-Provider Auto-Router (FreeLLMAPI style)** — user enters their available keys (Gemini, Groq, OpenRouter). The router prioritizes Google Gemini for deep reasoning, but automatically cuts over to Groq (LLaMA 3.3 70B @ 300 t/s) if Gemini is slow (>3.5s TTFT) or throttled.
   - Transparency: Message inspector pill showing exact provider, model, latency, and tokens/sec, plus a collapsible "View Injected Context" drawer.

## Refresher Drill Architecture & 404 Root-Cause Remediation

### Context & Diagnosis
Users reported that launching a Refresher Drill resulted in a `404 Not Found` error. An isolated reproduction script identified three root causes:
1. **Neon PostgreSQL Column Desynchronization**: Remote PostgreSQL `question_sets` table was missing the `module_id` column added in Plan 06, causing `db.insert(questionSets)` to throw `Postgres 42703 (column does not exist)`.
2. **Foreign Key Failure & Memory Desync**: The question set insert fell back to memory, but `createAttempt` failed foreign key validation when attempting to link to a non-existent database set ID.
3. **Unhandled Exception in Mock Store Question Mapping**: When `getAttemptForTaking` fell back to memory, `store.questions.get(item.questionId)!` returned `undefined` because question IDs from the database pool had not been mirrored into `store.questions`, crashing the server component with `TypeError: Cannot read properties of undefined (reading 'id')` and yielding a 404.

### Remediation & Architectural Overhaul
1. **Live Schema Push**: Executed `drizzle-kit push` to synchronize remote Neon database columns (`question_sets.module_id`).
2. **Defensive Attempt & Results Retrieval (`platform/lib/attempts.ts`, `platform/lib/grading.ts`)**:
   - `getAttemptForTaking` and `getAttemptResults` now safely check the fallback store if database queries return 0 rows.
   - Replaced fragile non-null assertions and map/filter patterns with typed `for ... of` loops that guard against missing question entries.
   - Ephemeral question sets generated in `assembleDailyRefresherDrill` now mirror all selected `finalQuestions` into `store.questions`.
3. **Multi-Topic SRS Drill Evaluation (`platform/lib/srs.ts`, `platform/lib/grading.ts`)**:
   - Refactored `updateTopicSrsAfterAttempt` to support multi-topic partitioning. When a drill attempt completes, answers are partitioned by question `microCluster`/topic code.
   - Each specific topic touched in the drill has its FSRS stability ($S$) and retrievability ($R = 1.0$) updated individually, ensuring daily refresher practice accurately clears students' due topic queues.
   - Cleaned domain resolution logic to parse subject prefixes correctly from `set.subjectTag` and drill titles stripped of the `⚡ ` emoji.
4. **Verification**: Executed automated end-to-end testing verifying drill generation, question retrieval, user answer submission, multi-topic SRS partitioning, and results viewing. Verified complete TypeScript compilation with `npx tsc --noEmit` (exit code 0).
